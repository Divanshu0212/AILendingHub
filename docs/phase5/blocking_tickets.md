# Phase 5 — Blocking ticket register

Every `TBD[owner, ticket-id]` placeholder raised by Phase 5 work appears here.
`make grounding` reads every `docs/phase*/blocking_tickets.md` and fails on any
placeholder that appears in none of them.

Earlier registers: [Phase 0](../phase0/blocking_tickets.md) ·
[Phase 1](../phase1/blocking_tickets.md) · [Phase 2](../phase2/blocking_tickets.md) ·
[Phase 3](../phase3/blocking_tickets.md) · [Phase 4](../phase4/blocking_tickets.md).
Two earlier tickets block Phase 5 directly and are not restated here:
**LH-203** (reason-code wording) is why no adverse-action template renders, and
**LH-111** (retention periods) is why conversation logs have no retention.

Phase 5 §8 puts these on the do-not-invent list: rates, fees and charges
(retrieval/tool-only) · adverse-action sentences (templates-only) · eligibility
rules (retrieval-only) · containment targets · retention periods for logs · any
answer where retrieval returned nothing. Each row below is a stop, not a gap in
the engineering.

| Ticket | Owner | Blocks | What is needed | Status |
|---|---|---|---|---|
| LH-601 | Product SMEs + Compliance | `assistant.registry`; every retrieval; every answer | The **document corpus** — product policy circulars, rate sheets, KFS templates and FAQs, each with a named owner, an effective-from date and a version. Phase 5 §3 makes "corpus owners named per document family" an entry criterion, and WS-5.1.1 makes the registry the first deliverable of the phase. Nothing here substitutes: another institution's circular is not a noisy version of this bank's, it is a different policy that answers a customer confidently and wrongly with a real-looking citation attached. | open |
| LH-602 | Product SMEs | `assistant.goldenset`; the WS-5.2 retrieval gate; every §7 exit criterion | The **golden set** — ≥ 500 question → answer → source-passage triples, per product and per language, including the fee edge cases and eligibility boundaries §4 names. This is `[DATA]` produced by people rather than found in a dataset, and it is derivative of LH-601: a triple's answer is only correct relative to a corpus, so the set cannot precede the documents it measures retrieval against. The harness that consumes it is built and tested; the set has no author assigned. | open |
| LH-603 | Compliance | `assistant.templates`; SRS GA-3; every decision explanation | The **adverse-action template library**, per language, keyed to P1 reason codes. Phase 5 §4 WS-5.3.3 is explicit that the assistant "never composes new decision-explanation sentences" — it selects and orders pre-approved ones. Distinct from LH-203, which is the *reason-code wording* in `config/reason_codes.yaml`: LH-203 is one sentence per code for a letter, LH-603 is the conversational template set with its ordering rules, its per-language variants and its required disclosures. Ratifying LH-203 does not produce LH-603. | open |
| LH-604 | GenAI squad + Model Risk | `assistant.ports`; every generated answer; the faithfulness gate | The **model bindings** — which LLM, which embedding model, which reranker, at which versions, under what data-residency terms. Not a code gap: `ports.py` defines all four seams and nothing in core imports a model. It is a procurement and model-risk decision that must be recorded before any answer is generated, because the faithfulness gate and the red-team suites are per-model and rerun on every model change (§5 step 2). | open |
| LH-605 | Product + Compliance | `assistant.faithfulness` containment reporting; Phase 5 §7 exit criterion 4 | The **containment target**. Phase 5 §7 writes it as `[POLICY: target]` and §8 puts containment targets on the do-not-invent list — the one exit criterion in the programme that ships with its own placeholder visible in the criterion text. It is a customer-experience decision rather than a tuning value: a high target pushes the assistant to answer where it should escalate, which trades the correct-escalation rate against it. | open |
| LH-606 | DPO | `assistant.guardrails` PII redaction classes; conversation-log retention | The **PII class list for conversational text** and the redaction policy over it. Phase 0's LH-110 classified *table columns*; a chat turn is free text in which a customer volunteers an Aadhaar number, an account number or a health reason for missing an EMI, and the class list that governs a schema does not tell a redactor what to look for in prose. Retention for the redacted logs is LH-111. Found by building. | open |
| LH-607 | Security + GenAI squad | `assistant.guardrails` injection scoring; the red-team gate | The **injection-detection decision threshold and the response to a detection**. Phase 5 §4 WS-5.4 requires treating retrieved chunks as untrusted and separating instruction from data, and names neither what score quarantines a chunk nor what happens to it — dropped silently, dropped with the answer marked, or the whole answer refused. The three differ in what the customer sees and in whether anyone learns the corpus was poisoned. Found by building. | open |
| LH-608 | Compliance + Product | `assistant.chunking` table handling; `assistant.registry` supersession | The **document supersession rule**. WS-5.1.1 gives every document an effective-from and an effective-to, which is enough to filter but not enough to decide the common case: two circulars are effective simultaneously and the later one amends the earlier in part. Retrieval that returns both lets the model pick; retrieval that returns the later one alone drops the unamended clauses. Neither is safe and the phase file names neither. Found by building. | open |
| LH-609 | GenAI squad | A Phase 5 Track P, if one is wanted | Whether to stand up a **public-document reference corpus** (RBI Master Directions and FAQs — real regulatory prose with real supersession chains and real exact tokens) to exercise chunking and effective-date filtering at realistic scale. It would produce no hit-rate number, because the question set is LH-602 and no public set matches this corpus. Raised rather than done: it is a scope decision, and ADR-0015 records that the gate does not move either way. | open |
| LH-610 | Compliance + Product SMEs | `assistant.goldenset` language slices; customer-facing launch | The **launch language list and the per-language slice size**. SRS GA-4 requires "≥ Hindi + English + 2 regional" and §4 WS-5.3.4 says a language ships only when its slice passes the same gates as English — which requires knowing which languages, and how many of the ≥ 500 triples each slice must hold for a hit-rate to mean anything. A 20-triple Hindi slice passing at 95% is four misses and a coin flip. Found by building. | open |
| LH-611 | Compliance | `assistant.answer` numeric-claim policy for tool results | Whether a number returned by an **allow-listed tool** may be stated without a document citation, and how it must be attributed. Phase 5 §4 WS-5.3.1 says numeric values "must come from a citation or a tool call" and §8 says rates and fees are retrieval/tool-only — so a tool-sourced EMI is permitted, but an EMI computed from a rate the customer supplied is arithmetic on an unverified input, and the answer contract cannot tell the two apart without a rule. Found by building. | open |
