# Phase 3 — Blocking ticket register

Every `TBD[owner, ticket-id]` placeholder raised by Phase 3 work appears here.
`make grounding` reads every `docs/phase*/blocking_tickets.md` and fails on any
placeholder that appears in none of them.

Earlier registers: [Phase 0](../phase0/blocking_tickets.md) ·
[Phase 1](../phase1/blocking_tickets.md). Tickets from both still block Phase 3 —
**LH-103** (default code sets) decides which loans are in the hazard model's
numerator, **LH-120** (data-sharing approvals) is why there is no bank panel at
all, and **LH-204** is why the P1 orchestrator has logged no decisions for a
staging baseline to be relative to.

Phase 3 §8 puts these on the do-not-invent list: SICR thresholds · downturn LGD
add-ons · CCF floors · macro scenarios · discount-rate conventions · segment
definitions for reporting. Each one below is a stop, not a gap in the engineering.

| Ticket | Owner | Blocks | What is needed | Status |
|---|---|---|---|---|
| LH-301 | Finance + Risk | `portfolio.staging`; the IFRS-9 Stage 2 feed; Phase 3 §7 staging audit | The SICR threshold: how much a lifetime PD must deteriorate against its value at origination before an account moves to Stage 2. SRS §7.3.4 illustrates "e.g., lifetime PD > 2× at origination" and Phase 3 §8 puts the threshold on the do-not-invent list, so the illustration is not the policy. The number sets the size of the Stage 2 book and therefore the ECL charge; a model that picks it is setting a provisioning level. `StagingPolicy.stage()` raises without it. | open |
| LH-302 | Risk Committee | `portfolio.lgd` downturn adjustment; ECL and any capital use | The downturn LGD add-on and the evidence behind it. Phase 3 §8 requires it be evidence-backed, which means a named downturn period and a measured uplift, not a flat percentage. Track P can *demonstrate* the arithmetic — the Fannie Mae 2007 vintage is a downturn cohort by construction — but a US mortgage crisis severity is not this bank's downturn add-on. | open |
| LH-303 | Risk Committee + Regulatory Reporting | `portfolio.ead`; every revolving-product EAD | Regulatory CCF floors, and which products they bind. Phase 3 §8 do-not-invent. Compounding this: **no revolving product exists on any track available here** — Fannie Mae is amortising term mortgages and Home Credit's revolving slice carries no limit history — so the CCF estimator has neither a floor nor data. `fit_ccf()` refuses rather than fitting the term-loan degenerate case, where `L == B₀` makes the denominator zero. | open |
| LH-304 | ICAAP / ALCO | `portfolio.macro` scenario application; the dashboard scenario widget; stress testing | The ratified macro scenario set — baseline, adverse, severely adverse — as factor paths, with the horizon each covers. Phase 3 §8 do-not-invent. The Wilson-style regression is fitted from data and is `[DATA]`; the scenarios it is *evaluated at* are policy, and a scenario invented to make a widget render becomes the bank's stress test. | open |
| LH-305 | Finance Controller | `portfolio.lgd` workout discounting; ECL | The discount-rate convention for workout cashflows: which rate (contract rate, EIR at origination, or the effective rate at default) and the convention for discounting to the default date. Phase 3 §8 do-not-invent. SRS §7.3.3 says "discounted at contract rate to default date", which names a rate but not the convention — monthly vs annual compounding, and whether the date is the default date or the last-paid-installment date, move LGD by more than most model choices do. `discounted_lgd()` raises without it; `realised_lgd()` computes the undiscounted figure, which is a different quantity and is labelled as one. | open |
| LH-306 | Risk Reporting + Finance | Every `portfolio.aggregates` segment cut; Phase 3 §7 dashboard criteria | The reporting segment definitions — how product, geography and portfolio are cut for management and regulatory reporting. Phase 3 §8 do-not-invent. The aggregation code takes a segmentation as an argument and ships none, because a dashboard whose segments were chosen by an engineer will be reconciled against Finance's numbers exactly once. | open |
| LH-307 | Risk Reporting | `portfolio.transitions` CUSUM alarms; `portfolio.health` drift alarms | The CUSUM reference shift `k` and decision interval `h` for the roll-rate alarms, and the ADWIN confidence `δ` for score-distribution drift. Phase 3 WS-3.2 names the *methods* and the cells to watch (30→60, 60→90) but no alarm parameters, and these set the false-alarm rate on a surface risk officers are expected to act on. Raised as a Phase 3 finding — the phase file's §8 list does not mention them, and an unparameterised "CUSUM alarm" reads as specified until code has to raise one. | open |
| LH-308 | Credit Risk Head | `portfolio.staging` SICR baseline; `portfolio.behavioral` origination-PD feature | The origination lifetime PD for accounts already on the book. SICR is defined as deterioration *relative to origination*, so it needs a lifetime PD as at each account's decision date. P1 produces one only for applications it scores from now on; for the existing book there is no such number, and the industry workaround — re-scoring today's loans with today's model on origination-dated features — is a proxy whose error is systematically correlated with vintage. Whether the bank accepts that proxy, and for which cohorts, is a policy call. | open |
| LH-309 | Credit Policy | `portfolio.lgd` stage 1 (cure model); the LGD population definition | The cure definition: what counts as a defaulted account returning to performing, and over what observation window. SRS §7.3.3 makes cure probability the first stage of the LGD model but Appendix A defines only *default*, not *cure*. The choice decides which defaults enter the recovery-rate model at all, so it moves LGD directly — and a cure rule that is looser than the default rule produces accounts that oscillate between states every month. | open |
| LH-310 | Model Risk + Credit Risk Head | `portfolio.hazard` monotone constraints; challenger promotion | The ratified monotonicity direction list for the **behavioural** feature set. LH-202 covers application features; the behavioural set is different (DPD trajectory, utilisation trend, times-in-arrears) and its directions were never ratified. `MonotoneConstraints.for_experiment` carries the Track P runs, which is exactly what it is for — an experiment reason string is not a constraint list, and `GBM.promotable` says so. | open |
